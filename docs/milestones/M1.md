# M1 — Orientation

**Status:** built 2026-10-17 on branch `m1-orientation`. 48 backend tests pass; the web app type-checks
and lints clean; the full flow was run by hand in the browser.

## Acceptance

| Criterion | Result |
| --- | --- |
| From five real policy documents, a draft handbook in under 2 minutes | Met with the offline drafter (under a second, five sample policies in Markdown, text, Word and PDF). **Not yet measured with Claude**: needs `ANTHROPIC_API_KEY`. The draft records its duration, tokens and cost so the first real run shows the number. |
| Every rule links to its source passage | Met. Every item carries passage labels (`2.7` = document 2, passage 7; `Q.first_check` = a questionnaire answer). Unknown labels are stripped on save, and an item with no source blocks approval. The UI opens the passage text from each label. |
| Approval is recorded | Met. Only a manager can approve; `approved_by`/`approved_at` are stored, the previous approved version becomes `superseded`, and the team's apprenticeships record the handbook version. |

## Built

- **Documents** (`app/orientation/extract.py`): PDF (with page numbers), Word, .txt and .md become
  passages of roughly 200–1200 characters. Duplicate uploads are detected by hash; a bad file is
  reported without blocking the rest of a batch.
- **Questionnaire** (`app/orientation/questionnaire.py`): six general questions plus one per decision
  option of each task type, generated from the task-type configs.
- **Model provider** (`app/llm/provider.py`): one interface for every model call.
  `AnthropicProvider` calls `claude-opus-5-5` with adaptive thinking, a JSON-schema output, streaming,
  and server-side refusal fallback; it reports tokens and cost. `FakeProvider` runs without a key.
- **Handbook** (`app/orientation/handbook.py`, `service.py`): fixed schema (purpose, procedures,
  decision rules, always-escalate, glossary, access scopes, escalation contacts, open questions),
  citation checks, stable item ids that are never reused, versioning, approval, revision.
- **Offline drafter** (`app/orientation/offline.py`): keyword rules that pull cited rule-like
  sentences from the sources, so the flow works end to end before a key is added.
- **API**: `/orientation/{teams,sources,passages,questionnaire,handbook/...}`, plus `/dev/users`
  (dev only) for the user picker.
- **Web** (`web/`): Next.js app shell with a dev user picker and the Orientation screen: upload,
  questionnaire, handbook with source chips, inline edit, add and delete, approve, and revise.
- **Samples** (`samples/accounts_payable/`): five fictional AP policies for demos and tests.

## Demo

```
cd backend
.venv\Scripts\python -m alembic upgrade head
.venv\Scripts\python -m app.seed
.venv\Scripts\python -m uvicorn app.main:app --port 8000
# second terminal
cd web
npm run dev
# third terminal, optional: load the sample policies
cd backend
.venv\Scripts\python scripts\upload_samples.py
```

Open http://localhost:3000/orientation. Act as the mentor to answer the questionnaire and draft;
switch to "Morgan (manager)" to approve.
