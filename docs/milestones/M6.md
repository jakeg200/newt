## Built

- **Manager dashboard** (`app/manager.py`, `/manager`): per team, the handbook version, task types by
  stage, cases handled (alone and approved), coverage, hand-back rate, audits, and hours returned
  from the manager's own minutes per case (history's time-to-decision is shown only as context; it's
  elapsed time, not effort). The cost line weighs the value of those hours, at the manager's hourly
  cost and currency, against the agents' running costs. No metric about the mentor appears;
  a test checks for it.
- **Production sign-in**: the API verifies Supabase access tokens (HS256 secret or the project's
  JWKS) and maps the email to a provisioned user. The dev header is refused outside development. The
  web app uses magic-link sign-in when the Supabase variables are set, and the user picker otherwise.
- **Provisioning** (`python -m app.admin`): create orgs, add people with roles, add teams with a
  task-type config.
- **Synthetic banner**: every screen of a synthetic org says so.
- **Deployment**: `backend/Dockerfile`, `fly.toml` (API and worker processes in Frankfurt; migrations
  on release), web on Vercel. Step-by-step in `docs/DEPLOY.md`.
- **Real Postgres**: `TEST_DATABASE=postgres python -m pytest` runs the suite on an embedded Postgres 16
  (template database, a fresh copy per test). All 163 pass.
- **Demo**: `python -m demo` (`--stop-before …`, `live N [--decide]`) and the video script in `docs/DEMO.md`.

## Fixed along the way

- **Re-probation couldn't pass at α = 2%.** The frozen record was capped at 150 cases, where even one
  error breaks the bound, so every model swap would have demoted. It now keeps the graduation
  evidence (up to 600 cases), and re-probation gets its own concurrency (48) to stay near 10 minutes
  with Claude.
- **"Both fine" didn't stick.** A re-prediction giving the same alternative the mentor had accepted was
  scored as an error again. Accepted alternatives (and "I'd change my call" exclusions) now carry over
  to later predictions of the same case, as the brief specifies.
- **Retrieval matched ids, not situations.** "Possible duplicate of INV-30012" retrieved invoice
  INV-30012 itself as the most similar case. Tokens containing digits no longer count towards
  similarity (they still drive capture matching). Offline agreement on the sample history went from
  about 93% to 99%.
- **A blocked action left the case half done.** When the policy stopped an autonomous reply, the status
  change still went through and the case was marked handled, so an invoice could be set to "query
  supplier" with no query ever sent. One blocked action now stops the whole case and hands it back to
  the mentor with the reason. Field updates a task doesn't allow are no longer planned at all, so
  "actions blocked" counts only what the policy actually stopped (it showed 72 for 36 ordinary cases).
- **Re-certification was flaky on the demo data.** 420 days of history from a fixed start date ran three
  weeks into the future, so live invoices counted as "earlier cases" for the newest history. Among
  identical-looking cases, the random case id decided which one was copied. In about 1 run in 6 the model
  swap found new reply errors, and 1 in 25 demoted. History now always ends on a fixed past date.
- **`python -m demo live` reused invoice numbers** from the programme's run. Numbering now continues
  from the last run, per database.
