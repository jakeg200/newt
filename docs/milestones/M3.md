## Acceptance

| Criterion | Result |
| --- | --- |

## Built

- **Case context** (`app/agents/context.py`): for each case, as of the moment its item arrived: the
  redacted item and its earlier thread, the approved handbook, active rules, and up to 5 similar
  past cases (TF-IDF over redacted text) whose mentor decision came before that moment. Each piece
  records when it existed.
- **Time-travel guard** (`check()`): timestamps on every piece, plus a scan of the item, handbook
  and rules for the mentor's own words on the case. It runs on every case of every backtest.
- **Agent output contract** (`app/agents/output.py`): one shape for every agent (decision, fields,
  text outputs, rationale, missing info, self-reported confidence), with a JSON schema generated
  from the task-type config.
- **Built-in apprentice** (`app/agents/builtin.py`): `claude-opus-5-5`, adaptive thinking, JSON
  schema output, refusal fallback, a cached system prompt (handbook and instructions, identical
  across a run), and 5 self-consistency samples whose majority is the decision and whose agreement
  share is the confidence.
- **Offline baseline** (`app/agents/offline.py`): does what the mentor did on the most similar past
  cases. Used when there's no API key, and a floor real agents should beat.
- **External agents** (`app/agents/external.py`, `registry.py`): register an HTTPS endpoint (HTTP
  localhost in dev); we POST each case with an HMAC-SHA256 signature. The signing secret is shown
  once and stored encrypted. Private, link-local and metadata addresses are refused. Bad answers,
  timeouts and errors are hand-backs.
- **Scorer** (`app/eval/score.py`): exact decision match; fields normalised (currency, numbers within
  0.5%, case and whitespace) and scored only where the mentor's value is known; agreement is the
  decision plus every observed critical field. Text outputs are marked pending for M4's judge.
- **Runner and worker** (`app/backtest/runner.py`, `app/worker.py`): a backtest is a job in the
  `jobs` table. In development the API runs jobs in-process; in production use
  `python -m app.worker`. Contexts are built and checked on one thread; agent calls run in
  parallel. Stats: agreement, a decision confusion matrix, field accuracy, agreement by confidence,
  cost, tokens, latency, duration.
- **Web**: Backtest screen with estimate-before-run, live progress, results, disagreements and
  hand-backs, and external agent registration.
- **Fix**: SQLite migrations now run with foreign keys off. Before, altering `agents` on SQLite
  cascade-deleted apprenticeships, task types and cases. This hit the dev database during M3 (only
  synthetic samples, reloaded since). A regression test now migrates a populated database down and
  up and checks nothing is lost. Postgres was never affected.

## Demo

API and web running as in M1.md. Then load the sample history as the invoice mentor: on Capture,
add a CSV connection with the column map in `samples/capture/ap_history_columns.json` and import
`samples/capture/ap_history_360.csv`. Open Backtest and start a 300-case run.

To try an external agent: register one with endpoint `http://localhost:8100/predict`, then, from
`backend/`:

```
set MOCK_AGENT_SECRET=<the signing secret you were shown>
.venv\Scripts\python -m uvicorn scripts.mock_agent:app --port 8100
```

and start a backtest choosing that agent.
